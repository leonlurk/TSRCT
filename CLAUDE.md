## Running the App

```bash
node server.js          # Start the bridge server (default port 3847)
npm start               # Same as above
```

A single-file Node.js HTTP server with zero npm dependencies. It serves the PWA and exposes the
API for tmux control, permissions, remote desktop, the session monitor, Tesla and auth. No build step, no
bundler — files are served directly from `src/`.

On Leon's machine it is NOT started by hand: `TSRCT.lnk` → `TSRCT.vbs` → `launch-tsrct.ps1`
(splash) → `boot-server.sh` → `node server.js`. The splash waits for the literal `[READY]` line
the server prints last in its listen callback — **if you change that line, fix the launcher regex**.

Environment (`.env`): `BRIDGE_TOKEN`, `BRIDGE_PORT` (3847), `BIND_HOST` (127.0.0.1),
`TMUX_SESSION` (**default `''`** — TSRCT opens with zero sessions and adopts the first real one),
`REMOTE_URL` (permanent Tailscale hostname, cosmetic — `tailscale serve` does the routing),
(`TUNNEL=1` is gone: the Cloudflare quick tunnel's binary was deleted 2026-09-08 and its code
2026-09-22 — remote access is Tailscale only),
`SESSION_IDLE_HOURS`,
`MORNING_AT` (default `06:00`) — **read in the process's local time, and WSL runs on UTC**: `.env`
carries `TZ=America/Argentina/Buenos_Aires` since 2026-09-21, when "06:00" rang his phone at 03:03,
`MORNING_ENABLED` (`0` turns the morning routine off),
`MORNING_MAX_SESSIONS` (default 4), `SCHEDULER_TICK_MS`, `PROJECTS_ROOT`,
`HERMES_AUTOSTART` (**default off, 2026-09-18** — TSRCT no longer touches the local model at boot:
no hermes warmup and no voice-embeddings worker, so Ollama is started separately and TSRCT never
pulls a model into the 8 GB card on its own. `=1` restores both. On-demand calls — dispatcher
ingest, TOWER, polisher — are unchanged and still degrade gracefully when Ollama is off),
`VAULT_ROOT`. `NTFY_TOPIC` / `NTFY_SERVER`: **no default topic** (an ntfy topic is a public name,
so unset means no ntfy alerts at all); the server's `sendNtfy()` is a **no-op** — only
`lib/dispatcher/ntfyPush.js` pushes. **Since 2026-09-19 `NTFY_SERVER` is this laptop** (`http://127.0.0.1:2586`, a
self-hosted ntfy under `systemctl --user ntfy`, reachable by the phone at
`https://<tailnet>:8444`): ntfy.sh's free tier is ~250 messages a day per IP and `lib/ring.js`

## Architecture

TSRCT (Tesseract Remote Control Terminal) is a mobile-first PWA for remotely controlling Claude
Code sessions running in tmux. Vanilla JS/CSS, no frameworks, no build step. Most JS files are
IIFE-wrapped modules exposing an explicit `window.*` API (Phase 3 de-globalization, 2026-06-15);
behavior is still wired via inline `onclick=` in `index.html`, so anything reachable from HTML or
another file must be on `window`.

### Server (`server.js`)
**~4100 lines**: boot, helpers and the auth gate. `handleAPI` is the gate plus a list of 15 route
groups, each in its own file under **`lib/routes/`** (2026-10-17), called in the old order; each answers
its routes or returns `NOT_MINE`. A group gets the server's state through `S` (built in server.js):
constants and helpers are taken from it per request, and a value the server changes over time is
ALWAYS read as `S.<name>` (never copied), so a route never acts on a stale one; a new mutable value a
route needs gets a getter (and a setter if it writes it) in `S`. A new route goes INSIDE a group
(check-routes fails if `handleAPI` grows past 150 lines, a group is defined in server.js, a route file
does not load, or a route is lost from `scripts/routes-baseline.json`; `--update` records new ones).
Checks that read the server's code as text use `scripts/serverSource.js` (server.js + lib/routes).
Runtime state goes in `.tsrct/` through `lib/stateFile.js` (2026-10-17): it moves an old root
`.tsrct-<name>` file in ONLY when the process is the server, newest copy wins, so a check can never
pull a file out from under the running server (`scripts/check-state.js`). The launcher's
`.tsrct-boot.log`/`.lock`/`-appid` stay at the root. Handles:
- Static serving (path-traversal guard) + CSP/security headers
- tmux interaction — all shell exec is argv-based (`execFileSync`/`spawnSync`, no shell
  interpolation) to prevent command injection. `tmux()` is the single argv choke point.
- Auth on every `/api/*` route: **WebAuthn / Windows Hello is the primary login** (2026-08-13),
  `BRIDGE_TOKEN` + TOTP 2FA as fallback, plus trusted-device sessions with a sliding idle window.
  The master token alone authorizes only LOCAL non-remote requests. `isRemoteRequest()` is
  **default-deny** (any proxy header ⇒ remote) — never narrow it back to one vendor's headers.
- Permission queue (Claude Code hooks push in; the UI approves/denies remotely)
- **Dispatcher** backend (`lib/dispatcher/`): the session monitor, the codemap engine, and
  `clickupAnalyst.js` — despite its name, the one runner every background `claude -p` job goes
  through (the ClickUp, worklog, digest and hours parts were removed from this public copy).
  **The Slack half is GONE (2026-09-19)**: the channel where tasks were typed, hermes
  classifying and routing them to sessions, the reconciler that drafted replies for stuck
  sessions, the prompt polisher, the researcher, the ClickUp webhook, TOWER, and the
  DISPATCHER tab/room. Leon: *"el dispatcher es lo del canal de slack donde ingreso tareas
  y hermes distribuye, eso esta todo muerto"* — and the three background loops that woke a
  4.7GB model on their own (TOWER every 25s, the Slack draft writer every 60s, the
  reconciler every 10s) died with it. **`@slack/bolt` went too: this repo now has ZERO npm
  dependencies.** What survives in `hermes.js` is only what a person asks for: the spoken
  brief, TALK's conversation and the session narrator.
  Working data is EPHEMERAL — `db.js` drops and recreates its tables on every startup (only
  `config` persists).
- Remote desktop (VNC + audio WS proxies, monitor rects), runners, SF CLI, Omni file browser
  (`/api/fs/*`), weekly audit (`/api/audit/*`)

### Key Singletons
- **`WorldManager`** — room registry + lazy CSS. `WorldManager.open('x')` / `.close('x')`.
  Only `remote` and `sfcli` are declared inside `world-manager.js`; every other room
  **self-registers** from its own module (`WorldManager.rooms.runners = {...}` at the bottom of
  `runners.js`, and likewise in automations). This is the actual
  pattern — follow it for a new room.
- **`Desktop`** — PC mode. Activated at viewport >= 900px. Rail sidebar (44px, one panel open,
  draggable `--sidebar-w`, Ctrl/Cmd+B to collapse) + the `SURFACES` registry driving `pcSwitchTab`.
- **`HF`** — hands-free voice mode. **`SessionVoice`** — session attention TTS.
- **`TermFocus`** / **`TermImg`** — terminal write gate and inline image rendering.
- **`tsrctWindows`** (`windows.js`) — window roles `full`/`deck`/`focus`/`wall`, swapped over the
  existing `BroadcastChannel('tsrct-windows')`; `pcExpandToScreen()` opens a second window on the
  other monitor via `GET /api/vnc/monitors`.

### Room System vs Desktop Surface
- A **room** is a mobile fullscreen modal: HTML `<div class="room" id="x-room">` in `index.html`,
  CSS at `src/css/rooms/room-x.css` (lazy-loaded on first open), and a registry entry that the
  room's own module assigns onto `WorldManager.rooms`. Add it to `sw.js` `ASSETS_TO_CACHE`.
- A **surface** is the desktop panel form of the same feature: one entry in `SURFACES`
  (`{title, el, css, init, teardown, where}`) plus its markup and a rail/tab button. Adding a
  panel is one registry entry — do NOT reintroduce per-panel if/else branches.

### Mobile vs Desktop
- Mobile is the base layout (every CSS file except `desktop.css`)
- Desktop adds `body.pc-mode` and a grid layout; `Desktop.buildPCLayout()` injects the PC DOM
- Many components check `document.body.classList.contains('pc-mode')` to pick the mobile or
  desktop element (terminal, input row, session list, …)

## The SecretCo contract (hard rule)

SecretCo/SecretCoSandbox is **AWS Bedrock only**. No SecretCo data may reach the public Anthropic API. In this
repo that means: never send SecretCo content to `claude -p`, to Hermes/Ollama, to ntfy, to Slack, or
into an HTTP response.

`lib/dispatcher/restrictedGuard.js` provides `mentionsRestricted()` / `taskIsRestricted()` / `assertNotRestricted()`.
It is required **standalone** in `server.js` — never reach it through `dispatcher.restrictedGuard`, or
the boundary silently depends on an optional subsystem having loaded.

**The gaps found on 2026-08-14 were closed on 2026-08-15**, at choke points rather than per call
site, because per-call-site is how they opened:

| Choke point | Covers |
|---|---|
| `gitCwd(res, {session, cwd, op})` | **all 18** `/api/git/*` routes. Responds 403 and returns null — never throws, because two routes had no enclosing `try` and several catches answer `{success:true}` with a 200, which would have reported a refusal as an empty result. |
| `sfAlias(res, raw, op)` | the 6 sf routes taking an org alias. `/api/sf/orgs` also filters SecretCo orgs out of the listing. |
| `analyst.submitJob()` | **every** headless-`claude -p` job kind — the morning brief, Tesla's workarounds and prompts, the taste picks — and any future one. |
| `promptPolisher.submit/submitFollowup` | had no SecretCo check at all; `submitFollowup` inlines a live pane capture. |
| `/api/runner/start` | the unguarded twin of the long-guarded `/api/hf/start`. |

Also guarded: hermes chat/embed, ntfy, core ingest, codemap (4 layers), voice corpus/embeddings,
vault write, `/api/fs/*`, `/api/termimg`, `/api/cwd`.

Filter restricted rows out of data BEFORE it reaches a job file, never by asking in the prompt: a
"HARD EXCLUSION" sentence asks the model not to look at something it has already been handed.
**A prompt is not a guard.**

**Deliberately NOT guarded — `/api/output`, `/api/session/output` and the terminal stream.** These
capture a tmux pane by name, including `secretco`, and the audit flagged them. They stay open because
driving the `secretco` pane from TSRCT **is the documented workflow** (`(removed)`: run it in a
runner, then target `secretco` from the session list). Blocking it would break the one sanctioned way
to do SecretCo work while protecting nothing — the pane content only becomes a breach if it reaches a
model or an external service, and every one of those paths is now guarded above.

**When you add any route or engine that reads a path, a cwd, a session name, or dispatches a
prompt, route it through the choke point above.** Fail closed. `npm run check` (`scripts/check-all.js`, **34 checks**, runs
every one and fails at the end; a new check goes in its list, and check-docs fails until this count matches; `npm run check:fast` skips check-brain and is
what the pre-commit hook from `npm run hooks` runs) runs `scripts/check-syntax.js` (every .js parses), `scripts/check-routes.js` (route inventory + auth gate) and
`scripts/check-restricted.js`, which fails if a new `/api/git/*` route skips `gitCwd`, if an sf alias is
sanitized without `sfAlias`, or if a dispatch function loses its guard.

**And never read a guard comment as evidence the guard exists** — `server.js` carried a
"belt-and-suspenders" SecretCo comment on worklog creation for months describing a check that was not
in the code. (It is implemented now.)

## Code Style

### No Emojis
- **NEVER use emojis in any code, comments, or UI elements**
- Use text symbols: `[*]`, `[+]`, `[-]`, `[!]`, `[?]`, `[>]`, `[x]`, `[S]`, `[i]`
- For icons, use monospace characters or inline SVG
- `scripts/check-emoji.js` enforces it (Unicode's colour-picture characters; Claude Code's own `❯ ✻ ✢` stay).

### CSS Architecture
- Mobile-first: mobile base lives in `base.css` / `layout.css` / `main.css`
- Desktop: `desktop.css` uses `@media (min-width: 900px)` AND `.pc-mode` together. Since
  2026-10-17 it is six files (`desktop.css`, then `desktop-runners/-attach/-notes/-git/-sessions.css`)
  linked in that exact order: the order IS the old cascade, so keep the `<link>` order.
- No dead rules (`scripts/check-css.js`) and no palette colour written as a literal
  (`scripts/check-colors.js`): write `var(--cyan)`, never `#00d4ff`, or the themes cannot reach it.
- Avoid `!important` — use higher specificity (28 in the tree; ~15 of them lazy, all in
  `desktop.css`'s newest third)
- Sidebar width is `var(--sidebar-w, var(--sidebar-w-default, 220px))`; breakpoints set the
  *default* only. **Never put a literal width back into `grid-template-columns`.**
- `variables.css` is the palette source of truth. The 284 literals that equalled a token became the
  token on 2026-10-17; `--neon` and `--amber` are still literals (another token shares each value),
  and colours that are no token (other alphas) stay literal.
- `components.css` holds only `.btn` (pruned 2026-08-15; its second `.modal` without the gotcha-16
  height cap is gone).
- Classes: mobile `.card`, `.header`, `.quick-bar`; PC `.pc-sidebar`, `.pc-main`, `.pc-terminal`;
  state `.active`, `.hidden`, `.visible`, `.working`

### JavaScript Conventions
- IIFE-wrapped modules with an explicit `window.*` export block at the bottom. Any function called
  from an inline `onclick=` (in `index.html` OR in that file's own generated HTML) or from another
  file MUST be exported on `window`, or it is a private ReferenceError. `onclick` can be
  multi-statement (`onclick="event.stopPropagation();fn()"`) — every name in it needs exporting.
  **The single most common defect class in this repo:** the curated export block covers
  `index.html` handlers and forgets the module's own generated HTML. 8 dead buttons found
  2026-08-14 that way.
- Shared mutable cross-file state uses window getters/proxies (`homeSession`, `sfOrgs`,
  `userCommands`), never a one-time `window.x = x` (which goes stale).
- Global objects: `Desktop`, `WorldManager`, `HF`, `SessionVoice`, `TermFocus`, `TermImg`,
  `tsrctWindows`
- Functions camelCase; constants UPPER_SNAKE
- `$('id')` = `document.getElementById` (app.js); `escapeHtml()`/`createSpeechRecognizer()` in
  `utils.js`
- Preferences go through `pcPrefGet/pcPrefSet(key, value, scope)`:
  `window`→`sessionStorage` (default), `browser`→`localStorage`, `server`→the `config` table.
  Scope is a per-window vs per-browser decision, not a durability one.
- **Any frontend change must bump `sw.js` `CACHE_NAME` (currently `tsrct-v429`).**

### Service Worker
`sw.js` caches the PWA shell, room CSS and room JS. Bump `CACHE_NAME` on every asset change and add
new room CSS/JS to `ASSETS_TO_CACHE`.

Assets are cached one by one (`cache.add` per file, failures reported), because `addAll` is atomic:
one 404 used to reject the whole install. If you delete a cached asset, remove it from
`ASSETS_TO_CACHE` in the same edit.
